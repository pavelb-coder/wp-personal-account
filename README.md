# WP Personal Account

**Версия: 3.66.6** · WordPress 6.0+ · PHP 7.4+ · GPL-2.0-or-later · текстовый домен `wp-personal-account`

Плагин личного кабинета для WordPress: профиль, пароль, смена email, команды пользователей, вход и регистрация — на шорткодах, без зависимостей и сборки.

**Что нового в 3.66.6:** поле «Класс» скрывается у наставников в профиле и административном списке аккаунтов без удаления сохранённого значения. Полная история — в [CHANGELOG.md](CHANGELOG.md).

## Что внутри

| Раздел | Шорткод / файл |
| --- | --- |
| Панель управления | wp-admin → «Личный кабинет» |
| Личный кабинет (вкладки, возврат на сайт и выход) | `[wppa_account]` |
| Команды аккаунтов | вкладка `team` |
| Форма входа (с кнопками «Регистрация» и «Вернуться на сайт») | `[wppa_login]` |
| Форма регистрации (с персональными данными) | `[wppa_register]` |
| Вход + регистрация одним блоком | `[wppa_auth]` / виджет |
| Виджет для главной | «Внешний вид → Виджеты» (классические темы) |
| Блоки для блочных тем | `wppa/auth` (оба), `wppa/login` (только вход), `wppa/register` (только регистрация) |

### Панель управления (wp-admin)

Отдельное меню **«Личный кабинет»** в админке, семь экранов:

* **Обзор** — пользователи всего / новые за 30 дней / подписчики / ожидают подтверждения email, график регистраций за 14 дней, состояние (страница кабинета, регистрация, вкладки), последние регистрации.
* **Конструктор** — сборка каждой вкладки кабинета из блоков: включение, порядок, заголовки, аудитория, свои HTML-блоки.
* **Аккаунты** — поиск по логину, email и имени, фильтр по роли, пагинация, команда пользователя, персональные данные (телефон, город, организация…), ожидающие подтверждения email.
* **Команды** — список команд, капитан, состав (участники без наставников + отдельная колонка «Наставники» с назначением и снятием), редактируемые минимум и лимит участников (свои на команду), отметка недобора, роспуск команды.
* **Рассылка** — две рассылки на одной странице (вкладки «Второй этап» и «Прикреплённые файлы»): шаблон письма, предпросмотр, очередь с задержкой между письмами, отмена и журнал у каждой свои.
* **Инструменты** — создать/восстановить страницу кабинета, сбросить блокировки входа, очистить заявки на смену email, экспорт аккаунтов в CSV (включая все включённые персональные поля).
* **Настройки** — прежняя страница настроек кабинета (переехала в это меню).

Все действия в «Инструментах» защищены nonce и правом `manage_options`, выполняются через `admin-post.php`.

### Кнопки входа и регистрации

Под каждой формой есть кнопка перехода на соседнюю — чтобы гость не искал ссылку:

* **Форма входа** — основная кнопка «Войти» + вторичная **«Регистрация»** (ссылка на `?wppa_view=register`). Кнопка есть только при открытой регистрации: `registration_enabled` в настройках плагина **и** «Настройки → Общие → Любой может зарегистрироваться».
* **Форма регистрации** — «Создать аккаунт» + вторичная **«Войти»**.
* **Экран гостя** в кабинете — те же формы, поэтому кнопки перехода теперь внутри них (раньше была мелкая текстовая ссылка).
* **Виджет и блок** в режиме «оба» кнопку не показывают — там уже есть вкладки «Вход / Регистрация», дубль не нужен. В режиме «только вход» (`mode="login"`) кнопка «Регистрация» выводится.
* Отключить кнопку можно атрибутом шорткода: `[wppa_login hide_register="1"]`, `[wppa_register hide_login="1"]`.
* В шаблонах кнопка управляется переменными `$hide_register` / `$hide_login` (переопределение шаблона в теме сохраняет поведение).
* Хелперы: `WPPA_Plugin::registration_open()`, `WPPA_Plugin::register_url()`, `WPPA_Plugin::login_url()`, `WPPA_Plugin::requested_view()`.

**Переход по кнопке работает в любом варианте размещения:**
* параметр `?wppa_view=register` зарегистрирован в `query_vars` — WordPress не выбрасывает его каноническим редиректом (раньше это ломало переход на главной странице);
* виджет и блок сами переключаются на регистрацию по этому параметру, даже если настроены «только вход»;
* в режиме «оба» вкладка «Регистрация» открывается сразу по ссылке;
* если ссылка ведёт на текущую страницу, JS переключает панель без перезагрузки;
* при закрытой регистрации параметр игнорируется и показывается вход.

Если кнопка всё равно не срабатывает: проверьте, что в **Настройках** выбрана страница кабинета (иначе ссылка ведёт на главную) и что страница кабинета не отдаётся из кэша плагина кэширования (исключите её из кэша — кабинет и формы не кэшируются из-за nonce).

### Минимальный возраст регистрации

В wp-admin → «Личный кабинет» → «Настройки» → «Основное» задайте **«Минимальный возраст при регистрации»** в полных годах (0–120); 0 отключает проверку. Значение по умолчанию — 0, поэтому существующие установки не меняют поведение. Ограничение действует на регистрацию через формы плагина, на всех пользователей, включая будущих наставников; стандартную форму WordPress и другие плагины оно не ограничивает.

Когда установлен возраст больше нуля, дата рождения обязательна на форме регистрации, даже если поле отключено в настройках персональных данных. Сервер проверяет корректность даты и возраст до создания аккаунта, по текущему дню в часовом поясе сайта; регистрация допускается в день достижения возраста. Для родившихся 29 февраля в невисокосный год днём достижения возраста считается 1 марта. Проверка не применяется к уже созданным аккаунтам и при редактировании профиля.

### Поля ФИО в профиле

В личном кабинете поля профиля расположены в порядке «Фамилия», «Имя», «Отчество», перед отображаемым именем. Для отчества сохраняются настроенные подпись, видимость и обязательность; значение, валидация и сохранение не изменены. В профиле поле показывается рядом с именем независимо от его раздела в настройках анкеты. Форма регистрации сохраняет свою настроенную раскладку.

### Персональные данные в регистрации и профиле

Форма регистрации собирает не только email и пароль: набор полей настраивается в админке
(**Личный кабинет → Настройки → «Персональные данные»**).

Редактор полей позволяет:

* **переименовать** любое поле — подпись в форме и в кабинете берётся из настроек;
* **перенести** поле в раздел и задать **порядок** вывода (число, меньшее — выше);
* **скрыть** поле галочкой «Показывать» и сделать его **обязательным**;
* **добавить своё поле**: ключ (латиница, цифры, подчёркивание), подпись, тип, раздел — до трёх полей за одно сохранение;
* **удалить своё поле** галочкой «Удалить» — значения остаются в базе, но поле исчезает из кабинета и из выгрузки;
* **добавить, переименовать и удалить разделы** — раздел это заголовок в форме регистрации и профиля.

Разделы по умолчанию: **Основные данные**, **Контакты**, **Работа** (порядок 10/20/30). Раздел «О себе» убран в 3.32.1: его id числится в `WPPA_Fields::retired_sections()`, поэтому сохранённые настройки старых сайтов его не воскрешают. Раздел «Основные данные» (`main`) удалить нельзя: в него переходят поля удалённого раздела. Поле, у которого раздел исчез, тоже не теряется — оно попадает в первый раздел.

Своё поле получает мета-ключ `_wppa_custom_{ключ}` и сразу участвует везде: в регистрации, в профиле, в админской таблице аккаунтов и в колонках выгрузки (группа «Личные данные»).

**Поле «Класс» у наставника.** Поле с подписью «Класс», «Школьный класс» или «Класс обучения» (без учёта регистра) и свои поля с ключом `class`, `klass` или `school_class` не показываются у наставника в профиле и административном списке аккаунтов. Другие поля и пользователи не затронуты. Скрытое обязательное поле не блокирует сохранение профиля; его сохранённое значение не удаляется и вновь появится, если пользователь перестанет быть наставником. Если поле названо иначе и имеет другой ключ, измените его подпись в настройках. Форма регистрации не меняется: на её этапе роль в команде ещё не назначена. CSV-выгрузка сохранённых данных не меняется.

Типы своих полей: текст, многострочный текст, телефон, email, ссылка, дата, число, список (варианты — по одному в строке), флажок. Сантизация и проверка идут по типу: телефон 5–20 цифр, дата по календарю и не в будущем, ссылка с протоколом, число принимает запятую и хранит точку, значение списка обязано быть среди вариантов.

```php
WPPA_Fields::registry();               // встроенные поля
WPPA_Fields::all();                    // встроенные + свои, с подписями из настроек
WPPA_Fields::sections();               // разделы: id => label, order, custom
WPPA_Fields::schema();                 // поля с разделом, порядком, enabled, required
WPPA_Fields::grouped( 'profile' );     // включённые поля по разделам
WPPA_Fields::options_of( $def );       // варианты списка
WPPA_Fields::types();                  // доступные типы своих полей
```

Своё поле можно добавить и кодом — фильтром `wppa_fields` (раздел задаётся ключом `section`).

| Поле | Тип | Хранение | По умолчанию |
| --- | --- | --- | --- |
| Фамилия | text | `last_name` | показывается |
| Имя | text | `first_name` | показывается, обязательно |
| Отчество | text | `_wppa_patronymic` | показывается |
| Телефон | tel | `_wppa_phone` | показывается |
| Дата рождения | date | `_wppa_birthdate` | скрыто |
| Город | text | `_wppa_city` | показывается |
| Организация | text | `_wppa_company` | показывается |
| Должность | text | `_wppa_position` | показывается |

Поля **«Сайт»** (`_wppa_website`), **Telegram** (`_wppa_telegram`) и **«О себе»** (`description`) удалены в 3.32.1: их больше нет ни в настройках «Персональные данные», ни в регистрации, ни в профиле, ни в валидации. Уже сохранённые значения в базе остаются нетронутыми — плагин их просто не показывает и не перезаписывает.

* Обязательные поля помечены звёздочкой (`*`): в регистрации — «Имя», «Email», «Пароль», «Пароль ещё раз» и согласие на обработку данных; во входе — логин и пароль; в смене пароля — все три поля. Под формой регистрации есть пояснение «Поля со звёздочкой (*) обязательны — без email и пароля аккаунт не создать».
* Те же поля выводятся в форме профиля (кроме «Имя» и «Фамилии» — там они нативные) и редактируются пользователем.
* Валидация: обязательные поля, телефон (5–20 цифр, формат `+7 900 000-00-00`), дата рождения (не в будущем, не раньше 1900), поля типа `url` (обязателен протокол — своих полей это тоже касается), длина текста до 190 символов.
* Имя выводится в порядке **«Фамилия Имя Отчество»** — так его собирает `WPPA_Teams::full_name()`: пустые части пропускаются («Сидоров Пётр» без отчества), а если не заполнено ничего — берётся отображаемое имя. Этим же порядком пользуются приветствие, команда, участники, файлы, сертификаты и админка; переопределить можно фильтром `wppa_full_name` (имя, пользователь).
* Отображаемое имя (то, что видит WordPress и письма) собирается при регистрации и сохранении профиля в том же порядке: «Фамилия Имя Отчество», а если все три поля пусты — из логина.
* Значения видны в кабинете (блок «Сводка профиля» → карточка «Личные данные»), в админке (колонка «Персональные данные») и в CSV-экспорте.
* При регистрации пишется метка согласия `_wppa_consent_time`.
* Новые поля добавляются в настройках или фильтром `wppa_fields`, новые коды ошибок — фильтром `wppa_notices`.
* Поля, снятые с показа, не выводятся и не валидируются; их значения остаются в базе (удаляются при удалении плагина с включённой опцией очистки).

### Вкладки кабинета

Вкладки: **Обзор** (дата регистрации, команда, кнопка со ссылкой — без email и личных данных), **Профиль**, **Команда**, **Файлы** (куратору всегда; наставнику — когда есть файлы куратора или отметка второго этапа), **Участники** (только куратору — отдельный раздел с баллами и порогом процента), **Сертификаты** (только когда есть что показать: свои сертификаты или сертификаты участников команды у наставника; куратору — всегда при активном WP Diplom), **Рассылка** (только куратору), **Безопасность** (пароль, смена email с подтверждением, выход).

**У куратора вкладок «Обзор» и «Профиль» нет** — он работает с командами, участниками и рассылкой, поэтому видит «Команда», «Файлы», «Участники», «Рассылка» и «Безопасность» (`WPPA_Template::tabs()` убирает лишние вкладки для `WPPA_Teams::is_curator()` и оставляет «Участники» и «Рассылка» только ему; вкладка по умолчанию берётся первая доступная).

Вкладки «Олимпиады» нет: баллы за тесты из плагина олимпиад попадают только в выгрузку аккаунтов.

### Блоки Gutenberg (блочные темы, FSE)

В блочных темах `widgets.php` отключён — там используются блоки плагина. В редакторе WordPress доступны:

| Блок | Что выводит |
| --- | --- |
| `wppa/auth` | Вход и регистрация одним блоком (вкладки) |
| `wppa/login` | Только вход: форма или кнопка «Войти» |
| `wppa/register` | Только регистрация: форма или кнопка «Регистрация» |
| `wppa/login-button` | Кнопка «Войти» для гостей |
| `wppa/logout-button` | Кнопка «Выйти» для авторизованных |
| `wppa/register-button` | Кнопка «Регистрация» для гостей |

`wppa/login` и `wppa/register` — независимые блоки: можно поставить кнопку входа в шапку, а форму регистрации на отдельную страницу, или наоборот. Три отдельных блока-кнопки можно разместить на странице, в записи или шаблоне сайта; в редакторе они находятся по названиям «Кнопка входа», «Кнопка выхода», «Кнопка регистрации». У каждой кнопки настраиваются подпись, стиль, размер, ширина, выравнивание, акцентный цвет, отдельные цвета фона, текста и рамки (в том числе при наведении), шрифт, отступы, рамка и скругление. В редакторе показывается пример кнопки; на сайте её видимость определяется авторизацией. Выход использует стандартную защищённую ссылку WordPress. Кнопка регистрации учитывает настройки регистрации и расписание: если регистрация выключена — скрыта; до начала или после окончания срока — неактивна.

#### Переходы отдельных кнопок

В боковой панели кнопки откройте **«Переходы»**. Для входа и регистрации можно указать страницу с формой плагина и отдельный адрес после успешного входа или регистрации; для выхода — адрес после выхода и подтверждение действия. Все три кнопки можно открывать в новой вкладке. Пустые поля сохраняют прежнее поведение: стандартная страница кабинета, настройка перехода после входа, кабинет после регистрации и выхода. Допустимы только адреса текущего сайта или пути от корня (`/страница/`), включая параметры. Если указанная страница использует собственную форму стороннего плагина, переход после авторизации она должна обрабатывать самостоятельно; встроенные формы WP Personal Account передают его автоматически, включая возврат к форме при ошибке. При заданном переходе кнопки он имеет приоритет над `redirect` формы входа. Выход всегда выполняется через `wp_logout_url()` с защитным nonce. Старые кнопки и настройки оформления продолжают работать как раньше.

Атрибуты блоков `wppa/login` и `wppa/register`:

| Атрибут | Значения | По умолчанию |
| --- | --- | --- |
| `display` | `form` — форма, `button` — кнопка-ссылка на форму | `form` |
| `buttonText` | текст кнопки | «Войти» / «Регистрация» |
| `hideForMembers` | скрывать от авторизованных | `true` |
| `redirect` | куда вести после входа/регистрации | пусто (в кабинет) |
| `showTitle` / `title` | заголовок блока | выкл. / «Войти» или «Регистрация» |
| `hideOther` | скрыть кнопку перехода на соседнюю форму | `false` |

Кнопка регистрации не выводится, если регистрация закрыта. Кнопки — обычные ссылки `.wppa-button` на `?wppa_view=login` / `?wppa_view=register`.

#### Настройка внешнего вида

У трёх блоков форм есть панель **«Внешний вид»** в боковой колонке редактора:

| Настройка | Значения | По умолчанию |
| --- | --- | --- |
| Оформление | «Без оформления» (наследует стили темы), «Карточка» (фон, рамка, тень), «Рамка» (фон и рамка) | без оформления |
| Ширина | по содержимому / узкая 320 px / средняя 420 px / широкая 560 px / на всю ширину | по содержимому |
| Размер кнопок | компактный / обычный / крупный | обычный |
| Кнопки на всю ширину | переключатель | выкл. |
| Стиль кнопки | основная (заливка) / вторичная (обводка) — для вида «кнопка» | основная |
| Акцентный цвет | палитра или HEX | из настроек плагина |
| Радиус скругления | px, 0 — по умолчанию | 0 |

Дополнительно работают **штатные панели WordPress** (за счёт `supports`): «Цвета» (фон, текст, градиент, цвет кнопок), «Отступы» (внешние и внутренние), «Рамка» (цвет, толщина, стиль, радиус), «Типографика» (размер, межстрочный, насыщенность), выравнивание wide/full и «Дополнительные CSS-классы».

Всё оформление делается классами и CSS-переменными (`--wppa-accent`, `--wppa-radius`) на обёртке блока — без инлайновых стилей на отдельных элементах, поэтому легко переопределить в теме:

```css
.wp-block-wppa-login.wppa-block--card {
	box-shadow: none;
	border-radius: 4px;
}
```

### Блок `wppa/auth`

* Вставляется в любом месте: Site Editor → «Шаблоны» → «Главная», или в редакторе страницы/записи; в списке блоков лежит в категории «Виджеты».
* Панель настроек блока: что показывать (оба / только вход / только регистрация), скрывать от авторизованных, редирект после входа, заголовок блока.
* Динамический блок: разметка готова на сервере (`render_callback`), в редакторе показывается живой предпросмотр через `ServerSideRender`.
* Сборка не нужна: `blocks/auth/index.js` написан на `wp.element.createElement`, зависимости (`wp-blocks`, `wp-block-editor`, `wp-components`, `wp-server-side-render`) регистрируются в PHP.
* Стили подключаются самим блоком; поддерживаются выравнивания wide/full и отступы (`supports.spacing`).

### Виджет входа и регистрации

Виджет **«Личный кабинет: вход и регистрация»** — компактный блок с переключателем «Вход / Регистрация» для главной страницы или сайдбара.

* Настройки виджета: заголовок, режим (только вход / только регистрация / оба), редирект после входа, «скрывать от авторизованных».
* Установка: «Внешний вид → Виджеты» → перетащить в нужную область. В блочных темах (FSE) — блок «Классический виджет» или «Шорткод».
* Если главная собрана блоками: шорткод `[wppa_auth]` (атрибуты `mode="both|login|register"`, `redirect="…"`, `hide="0"`).
* Стили подключаются автоматически, когда виджет активен или на странице есть шорткод; вёрстка адаптивная, кнопка на всю ширину, акцентный цвет берётся из настроек плагина.
* Формы работают без перезагрузки страницы-источника: обработчик на `template_redirect`, после входа — редирект в кабинет.

### Конструктор кабинета

Каждая вкладка кабинета собирается из блоков — как в редакторе страниц, только проще.

* Блоки: **Приветствие**, **Сводка профиля** (дата регистрации и команда), **Кнопка со ссылкой**, **Форма профиля**, **Команда**, **Смена пароля**, **Смена email**, **Сессия и выход**.
* Для каждого блока: включён/выключен, свой заголовок (или стандартный), аудитория — все пользователи или только администраторы.
* Порядок блоков = порядок на сайте; перестановка стрелками в панели.
* **Свои HTML-блоки** — произвольное число на вкладку: заголовок + HTML (проходит через `wp_kses_post`, скрипты вырезаются). Удобно для инструкций, памяток и ссылок.
* «Сбросить к стандартной» возвращает заводскую раскладку.
* Блоки, которых нет в плагине (например, после откатa версии), из раскладки выбрасываются: `known_items()` фильтрует их при чтении, а `drop_unknown()` вычищает из опции — если вкладка опустела только из-за такого блока, ей возвращается набор по умолчанию. Это делает `WPPA_Plugin::maybe_upgrade()` один раз на установку (флаг `wppa_layout_cleaned`).
* Если в вкладке нечего показать, администратор видит разное сообщение: «В этой вкладке выключены все блоки» (блоки есть, но сняты галочки) или «В этой вкладке нет ни одного блока» (добавлять нечего включать).
* Раскладка хранится в опции `wppa_layout`, шаблоны блоков переопределяются в теме: `yourtheme/wp-personal-account/blocks/{id}.php`.
* Новый блок добавляется фильтром:

```php
add_filter( 'wppa_blocks', function ( $blocks ) {
	$blocks['my-block'] = array(
		'label' => 'Мой блок',
		'tabs'  => array( 'dashboard' ),
		'desc'  => 'Что-то полезное',
	);
	return $blocks;
} );
```

и шаблоном `templates/blocks/my-block.php` (или в теме).

### Команды

Объединение нескольких аккаунтов в одну группу.

* **Капитан** создаёт команду, приглашает участников ссылкой-приглашением (живёт 7 дней) или письмом на email, исключает участников, назначает наставников, переименовывает и распускает команду.
* **Наставник** (роль `mentor`) может вести несколько команд: на вкладках «Команда» и «Файлы» выбирает нужную; видит сертификаты участников всех своих команд. В каждой команде может приглашать и исключать обычных участников, но не переименовывать и не распускать команду.
* **Участник** видит состав и может выйти самостоятельно.
* Капитан может назначить наставника из состава или пригласить существующий аккаунт по email. Наставник принимает или отклоняет приглашение в кабинете; оно действует 7 дней. Куратор может назначить существующий аккаунт по email или снять наставника в карточке команды. Администратор управляет ролями в админке. Наставник не может одновременно быть участником или капитаном другой команды.
* Роли хранятся в мете `_wppa_team_role`: `owner`, `mentor`, `member`; проверить права в коде — `WPPA_Teams::is_owner()`, `WPPA_Teams::is_mentor()`, `WPPA_Teams::is_manager()`.
* Счётчики: `WPPA_Teams::members_count()` — участники без наставников (это число сравнивается с лимитом и минимумом), `participants()` — тот же список пользователями, `mentors_count()` — сколько наставников, `members()` — все, включая наставников (для вывода состава).
* Приглашение — токен в мета команды, ссылка вида `?wppa_team_join=<токен>`. Действующий наставник может в любое время вставить общий код или ссылку в поле «Присоединиться к другой команде» на вкладке «Команда» и получить права наставника этой команды. Код действует 7 дней и сбрасывается при обновлении ссылки; повторное присоединение невозможно. При открытии ссылки без ввода в эту форму роль наставника автоматически не выдаётся. **Любой действующий наставник, получивший общий код, может присоединиться**, поэтому его следует передавать только тем, кому доверяют права наставника.
* **Наставник не считается участником**: он входит в состав команды, но не занимает место в лимите и не идёт в зачёт минимума. В кабинете это видно явно — «Участников: 2 из 10 (минимум 2) · наставников: 1 (в лимит не входят)».
* Лимит участников: общий — настройка `max_team_members` (2–100, по умолчанию 10) и фильтр `wppa_team_max_members`; **для каждой команды можно задать свой лимит** в админке («Команды» → колонка «Мин. / лимит»), пустое поле = общий лимит. Фильтр `wppa_team_limit` уточняет значение для команды.
* Минимум участников: общий — настройка `min_team_members` (1–100, по умолчанию 2) и фильтр `wppa_team_min_members`; для каждой команды можно задать свой минимум (фильтр `wppa_team_min`). Минимум не может превышать лимит. Команда ниже минимума получает отметку «недобор»: в кабинете — подсказка, сколько человек не хватает, в админке — бейдж и счётчик «Ниже минимума».
* Хранение: тип записи `wppa_team`; `_wppa_team_id` и `_wppa_team_role` остаются совместимы с прежней моделью. Дополнительные связи наставника — `_wppa_mentor_teams` у пользователя и `_wppa_mentor_ids` у команд; приглашения — `_wppa_mentor_invites`. Проверка прав по команде — `is_mentor_of()`, список — `mentor_team_ids()`. При выходе или роспуске удаляется только соответствующая связь.
* При удалении пользователя-капитана команда распускается автоматически.

### Куратор

**Куратор** — не роль в команде, а статус на уровне сайта: один человек следит за несколькими командами сразу (методист, преподаватель, организатор).

* Назначается в админке: **«Аккаунты»** → кнопка **«Сделать куратором»** в колонке «Действия»; там же — «Снять куратора». У куратора в списке стоит метка `куратор`.
* Статус хранится в мете пользователя `_wppa_curator` = `1`; API: `WPPA_Teams::is_curator( $user_id )`, `WPPA_Teams::set_curator( $user_id, true|false )`, `WPPA_Teams::curators()`, `WPPA_Teams::all_teams()`.
* В кабинете, на вкладке **«Команда»**, куратор видит карточку «Куратор: все команды»: название, капитан, число участников и наставников, состояние («сформирована» / «не хватает N» / «нет наставника»). Плашки «Вы куратор и не состоите в команде» и формы создания команды у него больше нет: куратор не занимает место в составе, и напоминать ему об этом незачем.
* В списке команд куратора кнопка **«Добавить файлы»** открывает файлы команды, а **«Открыть команду»** — карточку с назначением и снятием наставников. Куратор не видит полный состав и не исключает участников.
* В таблице команд у куратора вместо колонки «Капитан» — колонка **«Наставник»**: имя и фамилия наставника (`WPPA_Teams::full_name()`, при пустых имени/фамилии — отображаемое имя) и его email ссылкой `mailto:`. Если наставника ещё нет — «не назначен». Данные лежат в строках `WPPA_Teams::all_teams()` (`mentor`, `mentor_email`, `mentor_id`).
* Счётчиков «Участников» и «Наставников» в таблице куратора нет — только состав состояния: команда, наставник, состояние, отметка второго этапа и действие.
* Чего куратор **не** может: исключить капитана (сообщение «Капитана исключить нельзя»), распустить команду и выйти из неё — это дело капитана.
* На куратора **не действуют** лимит и минимум участников, и он **не получает кнопку перехода на внешнюю ссылку** — как наставник: блок ему не выводится вовсе (`status = curator`).
* Права в коде: `WPPA_Teams::can_manage_team( $team_id, $user_id )` — только капитан или наставник именно этой команды; куратор отдельно может управлять файлами и назначением наставников. `viewing_team_id()` определяет открытую куратором команду; наставник передаёт выбранную команду и сервер проверяет его привязку.
* Коды уведомлений: `curator_added`, `curator_removed`, `curator_already`, `curator_not`, `curator_invalid`, `team_captain_denied`, `team_curator_denied`.
* Куратору **недоступны приглашения и переименование**: карточек «Пригласить участников» и «Название команды» у него нет, а обработчики отклоняют такие запросы (`team_manager_only` / `team_owner_only`). Это дело капитана и наставника самой команды.
* `is_manager_of()` проверяет капитана или наставника конкретной команды, `is_captain_of()` — капитана. Куратор отдельно вправе назначать и снимать наставников, но не исключать участников и не переименовывать команду.
* После действия куратор остаётся в открытой команде: `WPPA_Teams::context_url( $team_id, $user_id )` возвращает адрес с `wppa_team`.

### Второй этап

Куратор отмечает команды, прошедшие во второй этап — это единственное действие с командой, которое ему оставлено.

* Кнопки «Отметить» / «Снять» в списке команд не открывают карточку команды: после нажатия куратор остаётся в списке (форма отправляет `wppa_stay=list`, обработчик в этом случае возвращает назад в список, а не на `?wppa_team=ID`). Переключатель на самой странице команды, наоборот, остаётся на месте.
* Где отмечать: в кабинете, карточка **«Куратор: все команды»** — колонка «Второй этап», кнопки «Отметить» / «Снять»; на странице открытой команды — ссылка «Отметить: команда прошла во второй этап».
* Кому видно: **всем участникам команды** и её наставнику — в карточке команды появляется бейдж «Ваша команда прошла во второй этап» с датой отметки; в админском списке команд — метка «второй этап» рядом с названием.
* На **главной странице кабинета** (вкладка «Обзор») участники и наставник команды сразу видят карточку `wppa-stage2--notice`: бейдж «Ваша команда прошла во второй этап» и название команды. Блок рисуется в шаблоне `templates/tab-dashboard.php` перед блоками конструктора, поэтому виден независимо от их настроек; бейдж дублируется в карточке «Команда» блока «Сводка профиля».
* Кто может: только куратор. Капитан, наставник и участники получают `stage2_denied` («Отмечать команды второго этапа может только куратор»).
* Хранение: мета команды `_wppa_team_stage2` = `array( 'time' => ..., 'user' => ... )`. API: `WPPA_Teams::stage2( $team_id )`, `is_stage2( $team_id )`, `set_stage2( $team_id, $on, $user_id )`; в строке `all_teams()` появился ключ `stage2`.
* Коды уведомлений: `stage2_added`, `stage2_removed`, `stage2_denied`, `team_missing_team`.
* **Снятие отметки и рассылка.** Снятие отметки сразу убирает ещё не отправленные письма этой команды из очереди рассылки — они не уйдут, а не «пометятся отправленными». Если отметку сняли **в течение минуты** после установки (`WPPA_Teams::STAGE2_GRACE = 60`), плагин считает нажатие случайным: письма не отправляются, в журнал рассылки пишется отдельная строка, а куратор видит сообщение «Отметка снята в течение минуты — сработала защита от случайного нажатия: письма этой команде не отправлялись» (`stage2_removed_grace`). При снятии с непустой очередью — `stage2_removed_mail`, без очереди — обычное `stage2_removed`. Дополнительно перед каждой отправкой проверяется, что отметка на месте: если её сняли в обход (`delete_post_meta`), письмо получает статус «пропущено» (`skipped`) и не отправляется.
* В CSV-выгрузку аккаунтов отметка не попадает — остаётся только в интерфейсе.

### Если файлы выгрузились не полностью

Уведомление «CSV записан, но файлы наставников выгрузились не полностью» (`folder_export_files_fail`) появляется только при реальных сбоях записи. Что теперь делается:

* Сбойная запись повторяется **один раз** — сетевые папки иногда отваливаются на мгновение.
* Каждый проблемный файл попадает в журнал выгрузки отдельной строкой: «Команда» → файл → причина (недоступная папка, нет прав, сетевая ошибка).
* Пропавший из `uploads` исходник — **не ошибка**: копия помечается как пропущенная (`skipped`), в сообщении пишется «Пропущено без исходника: N», предупреждение не показывается.
* Итог содержит числа: «Файлы наставников: выгружено X из Y, ошибок Z. Первая: …».
* В «Инструментах» появился блок **«Последняя выгрузка файлов наставников»**: время, выгружено/всего/ошибок, сообщение и до трёх строк с командой, файлом и причиной. Данные хранятся в опции `wppa_team_files_export_last` (`remember()` / `last_result()`), поэтому причину видно и после перезагрузки страницы.
* Кнопка **«Проверить папку команд»** (`WPPA_Team_Files_Export::probe()`) пишет и сразу удаляет пробный файл `.wppa-probe-*.txt` в `…/Команды`, а в журнал выгрузки пишет точный путь, режим доставки (`filesystem` / `smb`) и текст ошибки. Коды уведомлений: `files_check_ok`, `files_check_fail`.

**Сетевая папка (SMB) и вложенные каталоги.** Если путь задан как `\\server\share\…` и шара не смонтирована, запись идёт через `smbclient`. Утилита не создаёт вложенный путь одним `mkdir`: на `mkdir "olimp\Команды\1 (337)"` при отсутствующем родителе она отвечает `NT_STATUS_OBJECT_PATH_NOT_FOUND`. Поэтому каталоги создаются по одному уровню (`mkdir` + `cd`), причём **каждый шаг — относительным именем**: smbclient считает путь от текущего каталога, и полная цепочка после `cd olimp` дала бы `\olimp\olimp\Команды`. Ошибка «уже существует» (`NT_STATUS_OBJECT_NAME_COLLISION`) считается нормой, а файл кладётся **отдельным заходом**, повторив ту же цепочку переходов, и только после успешного `cd` — иначе при отсутствии папки файл оказывался бы в корне шары. Если папку создать нельзя, в причине пишется «smbclient не смог создать папку … (нет прав на запись?)». Проверить цепочку: функция `WPPA_SMB::smbclient_fatal()` (какие `NT_STATUS_*` фатальны) и кнопка «Проверить папку команд».

### Файлы: кто и когда прикрепляет

**Участник команды** видит файлы куратора в двух местах: на вкладке «Команда» — карточка «Файлы от куратора» (`templates/blocks/team-widget.php`, для всех, кроме куратора и наставника), и на вкладке «Файлы», которая появляется только тогда, когда куратор что-то прислал его команде (`WPPA_Curator_Files::can_use_tab()`, `has_curator_files()`). Внутри у него одна полка «Файлы от куратора» со ссылками на скачивание: формы загрузки нет, файлы наставника не показываются — их список фильтруется по направлению (`from === 'mentor'` отбрасывается). Пока куратор молчит, вкладки нет вовсе.
* **Куратор** прикрепляет документы для наставника в любой момент — отметка второго этапа ему не нужна.
* **Куратор** прикрепляет файлы **любой команде и без отметки второго этапа**, а после загрузки остаётся в разделе «Файлы» той же команды (скрытое поле `wppa_back=files`), а не перебрасывается в карточку команды — форма вынесена в отдельную карточку «Прикрепить файл» и не зависит от полки наставника.
* **Наставник** получает возможность прикреплять файлы, **когда команда прошла во второй этап**. До отметки блока «Файлы от наставника» нет совсем — ни формы, ни подсказки: наставник видит и скачивает только документы куратора. Блок появляется сразу после отметки (`WPPA_Teams::is_stage2()` в `templates/blocks/files-widget.php`).
* Проверка продублирована на сервере: `WPPA_Curator_Files::can_attach()` для интерфейса, а `store()` возвращает `WP_Error( 'wppa_file_stage2' )` → уведомление `file_stage2`. Участникам команды раздел недоступен, как и раньше.

**Несколько файлов за один раз.** Поле формы называется `curator_files[]` и несёт атрибут `multiple`, поэтому в диалоге выбора можно отметить сразу несколько документов (или перетащить их) — форма отправляется один раз, `enctype="multipart/form-data"` уже стоит в обеих формах: в карточке команды (`team-widget.php`) и в разделе «Файлы» (`files-widget.php`).

* `WPPA_Curator_Files::normalize_files( $files )` приводит `$_FILES` к плоскому списку: понимает и «многомерный» массив (`name`/`tmp_name`/`error`/`size` — массивы), и одиночное поле `curator_file` от старых форм. Пустые слоты (`UPLOAD_ERR_NO_FILE`, пустое имя) выбрасываются — браузер присылает их, когда выбрали меньше файлов, чем полей.
* `WPPA_Curator_Files::upload_many( $team_id, $files, $user_id )` обрабатывает каждый файл отдельно через `upload()` и возвращает `added`, `errors` (коды `WP_Error`), `count_added`, `count_failed`. Типы, размер (10 МБ) и лимит `MAX_FILES` проверяются **поштучно**: один плохой файл не отменяет остальные.
* Уведомления: `files_added` (прикрепилось больше одного), `file_added` (один файл — как раньше), `files_added_partial` (часть прикрепилась, часть нет — предупреждение с подсказкой про тип, размер и лимит). Если не прошёл ни один файл, показывается ошибка первого (`file_type`, `file_size`, `file_limit`, `file_empty`, `file_upload`).
* В тестах проверку «файл действительно пришёл из формы» (`is_uploaded_file()`) можно отключить фильтром `wppa_skip_upload_check` — временные файлы создаются на диске, а не браузером.

### Рассылка участникам второго этапа

Письма получают **все, кто в команде**: участники, капитан и наставник — по командам с отметкой «прошла во второй этап».

**Админка → «Личный кабинет» → «Рассылка»**

* **Шаблон**: тема и текст. Подстановки: `{имя}`, `{фамилия}`, `{команда}`, `{роль}`, `{дата_отметки}`, `{email}`, `{сайт}`. Текст превращается в HTML-письмо (абзацы — пустой строкой, переносы — `<br>`), отправляется с заголовком `Content-Type: text/html`.
* **Предпросмотр** — на реальном получателе: видно, что именно придёт в письме.
* **Задержка**: «интервал между письмами, минут» (по умолчанию 5, `0` — без пауз) и «писем за один запуск» (1–50). Первое письмо уходит сразу, каждое следующее — не раньше, чем через интервал. Отправку двигает WP-Cron (хук `wppa_mailing_tick`, одиночное событие на конкретное время), поэтому в админке видно «следующее письмо — дата и время».
* **Галочка «не отправлять повторно»** — для наставника метка отправки учитывает команду: письмо для другой команды не пропускается. Очередь проверяет привязку перед отправкой. Уведомления о сертификатах по-прежнему не направляются наставникам.
* **Очередь**: всего / отправлено / осталось / ошибок, шаг, следующее письмо, раскрывающийся список писем со статусами, кнопки «Отправить остаток сейчас» и **«Отменить рассылку»**.
* **Снятие отметки**: письма команды, у которой сняли отметку второго этапа, удаляются из очереди (кнопка «Снять», API `WPPA_Mailing::drop_team()`); в статусах появляется строка «Пропущено (отметка снята)». Перед отправкой каждого письма отметка проверяется ещё раз. У рассылки о прикреплённых файлах `drop_team()` вызывает удаление файла — см. ниже.
* **Ошибки**: если `wp_mail()` вернул ошибку 5 раз подряд, рассылка **сама встаёт на паузу** (в кабинете куратора и в админке видно причину), дальше — «Продолжить рассылку» или «Отменить». Всё пишется в журнал (40 последних записей).

**Кабинет куратора.** На главной странице куратор видит карточку «Рассылка участникам второго этапа»: сколько писем всего, сколько отправлено и осталось, когда следующее, причина паузы — и кнопку **«Отменить рассылку»** (форма `wppa_action=mailing`, `wppa_mailing_action=cancel`, nonce `wppa_mailing`). Остальным ролям кнопка недоступна — код `mailing_denied`.

API: `WPPA_Mailing::recipients()`, `settings()`/`save()`, `start()`, `cancel()`, `resume()`, `send_all()`, `clear()`, `process_due()`, `run_cron()`, `stats()`, `run_state()`, `next_run()`, `logs()`, `placeholder_list()`, `render()`, `to_html()`; опции `wppa_mailing` (шаблон и настройки), `wppa_mailing_run` (очередь), `wppa_mailing_log` (журнал).

### Рассылка о сертификатах

Третья рассылка куратора — в том же блоке `mailing-widget` на вкладке «Рассылка» (`WPPA_Mailing_Certificates`, шаблон пишется там же). Получатели — **участники и капитаны команд, которым сертификат уже выдан**; наставники не входят, команды без сертификатов тоже, отметка второго этапа не нужна.

* **Что подставляется**: к общим подстановкам добавляются `{номер}`, `{программа}`, `{дата_выдачи}` и `{сертификатов}` — данные последнего выданного сертификата (одно письмо на человека, сколько всего сертификатов — подсказывает `{сертификатов}`). Подстановки собирает `WPPA_Mailing_Certificates::placeholders()`, список для подсказки — `placeholder_list()`.
* **Своё хозяйство**: опция `wppa_mailing_certificates`, очередь `wppa_mailing_certificates_run`, журнал `wppa_mailing_certificates_log`, метка «уже отправлено» `_wppa_mailing_certificates_sent`, крон `wppa_mailing_certificates_tick` — три рассылки не мешают друг другу.
* **Очередь и журнал**: те же кнопки, что у других рассылок — «Сохранить шаблон», «Поставить в очередь», досрочная отправка остатка, отмена, очистка журнала. Состояние очереди видно куратору на «Обзоре» карточкой «Рассылка о сертификатах».
* **Снятие из очереди**: когда у команды больше нет сертификатов (сертификат убрали из кабинета), письма этой команды снимаются автоматически (`drop_team()` в `WPPA_Certificates::remove()`).
* **Админка**: у страницы «Рассылка» появилась третья вкладка «Сертификаты» (`wppa_kind=certificates`).

### Рассылка о прикреплённых файлах

Вторая рассылка — **о прикреплённых файлах**: письмо говорит, что в кабинете появились документы. Получатели — участники, капитан и наставник **тех команд, которым куратор прикрепил файлы** (`WPPA_Curator_Files::has_curator_files()`). Отметка «прошла во второй этап» для неё не требуется — куратор прикрепляет файлы любой команде; а вот команда без файлов (или та, у которой файлы удалили) в список получателей не попадает.

* **Отдельно от первой**: свой шаблон (по умолчанию — «Для команды «{команда}» прикреплены файлы»), своя очередь, свой журнал и своя метка «уже отправляли». Рассылки друг другу не мешают: можно отправить обе, можно отменить одну, не тронув вторую.
* **Удалили файл — убрали письма и получателя**: `WPPA_Curator_Files::remove()` (и `clear()` при роспуске команды) вызывает `WPPA_Mailing_Files::drop_team()`, поэтому pending-письма этой команды из очереди исчезают — как и при снятии отметки второго этапа. В журнале остаётся строка «Команда «…»: файлы команды удалены, из очереди убрано писем — N». Из списка получателей команда тоже пропадает: его считает `team_allowed()`. Удаление файлов наставника очередь не трогает: письмо о них и не пишет.
* **Проверка перед отправкой**: `process_due()` снова спрашивает `team_allowed()` — если файлы удалили, пока письмо ждало очереди (например, мету почистили в обход формы), письмо получает статус «пропущено» с причиной «файлы команды удалены», а не уходит вслепую.
* **Где управлять**: в кабинете куратора — второй блок в разделе «Рассылка» (форма несёт скрытое `mailing_kind=files`); в админке — вкладка «Прикреплённые файлы» на странице «Рассылка» (`admin.php?page=wppa-mailing&wppa_kind=files`).
* **Карточка на главной** куратора появляется для каждой запущенной рассылки отдельно, у каждой своя кнопка «Отменить рассылку».
* **Класс**: `WPPA_Mailing_Files extends WPPA_Mailing` переопределяет шаблон по умолчанию, константы хранения — `wppa_mailing_files`, `wppa_mailing_files_run`, `wppa_mailing_files_log`, мета `_wppa_mailing_files_sent`, крон `wppa_mailing_files_tick` — и два фильтра: `needs_stage2()` (возвращает `false`: отметка не нужна) и `team_allowed( $team_id )` (возвращает `has_curator_files()`: команда в списке, только пока у неё есть файлы куратора). `team_allowed()` учитывают `recipients()` и проверка перед отправкой в `process_due()`; `drop_team()` убирает письма команды из очереди. Код рассылки отдаёт `kind()` (`stage2`/`files`/`certificates`), класс по коду — `WPPA_Mailing::class_of()`.

* **Класс рассылки о сертификатах**: `WPPA_Mailing_Certificates extends WPPA_Mailing` — `kind()` = `certificates`, `needs_stage2()` = `false`, `team_allowed()` = `WPPA_Certificates::team_has()`, переопределены `recipients()` (только участники с сертификатом), `placeholders()`/`placeholder_list()` (добавлены `{номер}`, `{программа}`, `{дата_выдачи}`, `{сертификатов}`) и шаблон по умолчанию.

### Выгрузка файлов наставника в сетевую папку

**Структура папок.** Папки всех команд группируются в отдельную папку **«Команды»**, внутри — папка с названием команды, без номера: `\\10.200.10.10\kvant\olimp\Команды\Студия «Вектор»\протокол.pdf`. Переименовали команду — переименуется и папка при следующей выгрузке. Одноимённым командам достаётся « (2)», « (3)» по порядку номеров (считаются команды с меньшим номером), поэтому папки не сливаются и имя не зависит от порядка обхода. Имена считают `folder_root()` (общая папка, меняется фильтром `wppa_team_files_export_root`; пустая строка — без группировки), `folder_name()` и `folder_path()`; служебные символы вычищает `clean_name()`. Папка создаётся с первым файлом наставника; когда файлов не осталось, убираются и папка команды, и опустевшая общая.


**Кнопка «Экспортировать»** (Настройки → «Сетевая папка» и Инструменты → «Экспорт в сетевую папку») выгружает не только CSV аккаунтов, но и **файлы наставников всех команд**: `WPPA_Team_Files_Export::export_all()` проходит по командам, берёт файлы только с полки наставника (`from === 'mentor'`) и раскладывает их в подпапки с названием команды. Кураторские файлы не выгружаются. Повторное нажатие перезаписывает те же файлы под теми же именами — дублей и суффиксов `-a1b2c3` не появляется (имя берётся из меты `_wppa_team_export_files`).

* Папка берётся из «Сетевой папки»; если она не заполнена — из «Экспорт в папку» (`WPPA_Team_Files_Export::bulk_config()`), чтобы CSV и файлы команд оказывались в одном месте.
* Итог дописывается в журнал выгрузки: «Файлы наставников выгружены: N в M командах» / «… выгрузилось не полностью».
* Коды уведомлений: `folder_export_ok` (CSV и файлы), `folder_export_files_fail` (CSV записан, файлы — нет), `folder_export_fail` (не записался CSV).

Файлы, которые прикрепляют наставники, автоматически копируются в сетевую папку из настроек (**Настройки → Личный кабинет → Сетевая папка**).

* Под каждую команду создаётся своя подпапка: `<путь из настроек>/<название команды> (<ID>)`, например `Студия «Вектор» (12)`. Номер в имени не даёт папкам сливаться при одинаковых названиях; служебные символы `\ / : * ? " < > |` заменяются пробелами, длина названия ограничена 60 символами.
* Выгружаются только файлы наставников (`from = mentor`). Файлы куратора остаются в кабинете: папка нужна для документов, которые присылают наставники.
* Файл в кабинете никуда не девается — в сетевую папку идёт копия. Если файл с таким именем в папке команды уже есть, к имени добавляется короткий ключ (`протокол-a1b2c3.pdf`), чтобы не перезаписать чужой документ.
* **Удаление файла в кабинете копию в сетевой папке не трогает**: папка команды служит архивом документов наставника, поэтому файл убирается только из кабинета (метка `_wppa_team_export_files` остаётся — повторное прикрепление того же документа пишется под прежним именем). Вернуть прежнее поведение можно фильтром `wppa_team_files_remove_copy` → `true`. Роспуск команды по-прежнему убирает папку целиком (если она опустела).
* Выгрузка включается автоматически, как только задан путь. **Отключить** можно галочкой **«Настройки → Экспорт в папку → Копировать файлы наставников в папки команд»** (`wppa_settings[file_export]`, по умолчанию включена): файлы тогда остаются только в кабинете, при прикреплении ничего не копируется, «Экспортировать» пишет только CSV аккаунтов, а в «Инструментах» вместо кнопки «Проверить папку команд» висит предупреждение. Второй способ — фильтр `wppa_team_files_export` → `false`. Путь, логин и пароль — те же настройки `smb` (`path`, `user`, `pass`), что и у выгрузки CSV; поддерживаются обычная/смонтированная папка, UNC, `smb://`, php-smbclient и утилита `smbclient` (папка команды создаётся на шаре).
* Сбой сети не ломает загрузку в кабинете и **не показывается пользователю**: файл сохраняется, наставник видит обычное «файл прикреплён», а неудача копирования уходит в журнал выгрузки (`WPPA_Export_Folder::log_entry( false, … )`) — причина видна в «Инструментах» и на странице выгрузки. Код `file_export_failed` в реестре уведомлений остался, но при прикреплении больше не используется; успех — `file_exported`.
* API: `WPPA_Team_Files_Export::enabled()`, `folder_name( $team_id )`, `local_dir( $team_id )`, `record( $team_id )`, `export( $team_id, $path, $name, $key )`, `remove()`, `clear()`; запись о выгруженном хранится в мете команды `_wppa_team_export_files`. В `WPPA_SMB` появились `write( $name, $contents, $config, $subdir )`, `delete( $name, $config, $subdir )`, `remove_dir( $path )`.

### Файлы куратора

Куратор и наставник обмениваются документами по команде: куратор прикладывает файлы для наставника, наставник — свои файлы для куратора. Участникам команды раздел недоступен.

* Куратор: карточка **«Файлы для наставника»** на вкладке «Команда» (в любой команде, открытой кнопкой «Добавить файлы» или ссылкой `?wppa_team=ID`): загрузка, список с колонкой «От кого» (`куратор` / `наставник`) и удаление с подтверждением. Куратор удаляет любые файлы команды.
* Наставник: **отдельная вкладка «Файлы»** (пятая в кабинете, между «Командой» и «Безопасностью»): полка «Файлы от куратора» со ссылками на скачивание и своя полка — форма загрузки и список присланного, где он удаляет **только свои** файлы.
* **Групповая отправка куратора**: на вкладке «Файлы» без открытой команды есть карточка «Отправить файлы командам второго этапа» — один раз загружаются документы (`curator_files[]`, можно несколько), отмечаются команды в списке (`bulk_teams[]`, в списке только команды второго этапа, `WPPA_Curator_Files::stage2_teams()`), и каждая получает свою копию файла в кабинете. Ничего не отмечено — файлы уходят всем командам второго этапа. Обработчик — `curator_file_action=bulk`, метод `WPPA_Curator_Files::bulk_upload()` (каждой команде своя копия загруженного файла), коды уведомлений `files_bulk_sent`, `files_bulk_partial`, `files_bulk_nobody`, `files_bulk_denied`. Файлы куратора в сетевую папку не выгружаются — там только файлы наставников.
* Вкладка «Файлы» выводится только наставнику команды и куратору: `WPPA_Curator_Files::can_use_tab()`; остальным её нет ни в навигации, ни по прямой ссылке. Блок раздела — `files-widget` в «Конструкторе», шаблон `templates/blocks/files-widget.php`, вкладка — `templates/tab-files.php`.
* Куратор на вкладке «Файлы» без выбранной команды видит список команд с числом файлов и кнопкой «Открыть» (`?wppa_tab=files&wppa_team=ID`), с выбранной — документы команды и ссылку на управление ими на вкладке «Команда».
* Участники команды, капитан и посторонние файлов не видят; прямой адрес к папке ничего не отдаёт.
* Ограничения: до 20 файлов на команду, до 10 МБ каждый. Типы: `pdf`, `doc(x)`, `xls(x)`, `ppt(x)`, `txt`, `csv`, `rtf`, `odt`, `ods`, `odp`, `zip`, `rar`, `7z`, `jpg`, `jpeg`, `png`, `gif`, `webp`. Фильтры: `wppa_curator_file_max_size`, `wppa_curator_file_types`.
* Хранение: папка `uploads/wppa-curator/` (в ней `index.php` и `.htaccess` с запретом прямого доступа); список файлов — мета команды `_wppa_curator_files`: ключ → имя, файл на диске, размер, время, автор.
* В записи файла хранится направление: `from = curator|mentor`; у файлов, прикреплённых до 3.14.0, поле отсутствует и читается как `curator`.
* Скачивание идёт только через `admin-post.php?action=wppa_curator_file&team=ID&file=KEY&_wpnonce=…` после проверки прав и одноразового ключа `wppa_file_{team}_{key}`; отдаётся как `application/octet-stream` с заголовком `attachment`.
* Удаление файла и роспуск команды убирают файлы с диска.
* Права: `can_view( $team_id, $user_id )` — куратор, наставник команды и администратор; `can_manage()` — куратор и наставник этой команды; `direction()` — в каком качестве прикрепляет файл (`curator` / `mentor`, это же значение хранится в записи); `can_remove( $team_id, $key, $user_id )` — куратор удаляет любой файл, наставник только свой. API: `files()`, `count()`, `store()`, `upload()`, `remove()`, `clear()`, `download_url()`, `size_label()`.
* Коды уведомлений: `file_added`, `file_removed`, `file_missing`, `file_type`, `file_size`, `file_empty`, `file_limit`, `file_save_failed`, `file_forbidden`, `file_team_missing`.

### Участники и баллы: список, проценты и порог

Отдельный раздел куратора — вкладка **«Участники»** (`participants` в `WPPA_Template::all_tabs()`, шаблон `templates/tab-participants.php`), внутри — блок `participants-widget` («Участники и баллы») в «Конструкторе». По умолчанию блок стоит именно на этой вкладке (`default_tabs` в `WPPA_Builder::blocks()`, `WPPA_Builder::defaults()`), но его можно поставить и на «Файлы» — блок разрешён на обеих вкладках. Существующим установкам при обновлении блок переезжает с «Файлов» на свою вкладку (`maybe_upgrade()` → `drop_block()` + `seed_block( 'participants-widget', 'participants' )`, флаг `wppa_participants_tab`). Класс — `WPPA_Participants`, шаблон блока — `templates/blocks/participants-widget.php`.

* **Кому виден**: только куратору — вкладка «Участники» скрыта от остальных в `WPPA_Template::tabs()`, а шаблон блока выходит сразу, если `WPPA_Participants::can_manage()` (это `WPPA_Teams::is_curator()`) ложно. Участникам, капитанам и наставникам нет ни вкладки, ни блока.
* **Кто в списке**: `WPPA_Participants::rows()` → `WPPA_Teams::participants()` — капитан и участники, **без наставников**. Без открытой команды показываются все команды (`all_teams()`), с открытой (`?wppa_team=ID`) — только её участники.
* **Баллы и процент**: `WPPA_Participants::scores()` → `WPPA_Olympiad::summary_map()` — один запрос на весь список: тесты, сумма баллов, максимум, процент и число работ на проверке. Если плагина олимпиад нет (`is_active()`), вместо цифр — «—» и подсказка об интеграции.
* **Порог процента**: форма `wppa_action=participant_threshold`, nonce `wppa_participant_threshold`, поле `min_percent` (0–100). Хранится в `wppa_settings[participant_min_percent]`, по умолчанию 60; чтение — `WPPA_Participants::min_percent()` (фильтр `wppa_participant_min_percent`), запись — `set_min_percent()` с ограничением 0–100, сравнение — `below_threshold()`.
* **Как это видно**: под формой подпись «Порог N%: ниже него — X из Y участников» (`count_below()`), у строки с низким процентом значок `wppa-badge--warn` и подпись «ниже порога N%», у остальных — `wppa-badge--ok`. Процент выводит `percent_label()`: «75 %» без лишнего нуля, «72,5 %» с десятыми.
* **Коды уведомлений**: `participant_threshold_saved`, `participant_threshold_forbidden`.

### Сертификаты (интеграция с WP Diplom)

Сертификаты выдаёт плагин [WP Diplom](https://github.com/pavelb-coder/wp-diplom) — он делает номер, код проверки и PDF. Кабинет только показывает выданное и отдаёт файл. **WP Diplom не обязателен**: пока его класс `WPDC_Certificate` не объявлен, вкладки «Сертификаты» нет, а в списке участников вместо кнопок стоит подпись «нужен WP Diplom».

* **Куда**: вкладка **«Сертификаты»** (`certificates` в `WPPA_Template::all_tabs()`, шаблон `templates/tab-certificates.php`) и блок `certificates-widget` («Мои сертификаты») в «Конструкторе». Класс — `WPPA_Certificates`, шаблон блока — `templates/blocks/certificates-widget.php`.
* **Кому видна вкладка**: только тем, у кого есть что показать — участнику свои сертификаты (`count() > 0`), наставнику ещё и сертификаты участников его команды (`team_has()`). Нет сертификатов — нет ни вкладки, ни блока (шаблон выходит сразу, пустой карточки не остаётся). Куратору вкладка нужна всегда, пока активен WP Diplom (`available()`): он их выдаёт.
* **У куратора вкладка ведёт в плагин**: пункт «Сертификаты» в навигации кабинета — это ссылка на экран WP Diplom `edit.php?post_type=wpdc_certificate` (`WPPA_Certificates::admin_url()`, фильтр `wppa_certificates_admin_url`), открывается в новой вкладке. Ссылку строит `WPPA_Template::tab_link( $slug )` (возвращает `url`, `external`, `target`; фильтр `wppa_tab_link`), а помечает её стрелкой `↗` класс `wppa-nav__link--external`. Если открыть `?wppa_tab=certificates` напрямую, куратор увидит карточку «Сертификаты — в плагине WP Diplom» с кнопкой «Открыть WP Diplom» и ниже — список выданных сертификатов с панелью редактирования.
* **Выдача**: в блоке «Участники и баллы» у куратора в строке участника — кнопка «Выдать» (или «Ещё» для повторной выдачи) и «Убрать» у уже выданного; под таблицей — секция «Сертификаты участников» с единственной кнопкой «Выдать всем, кто выше порога». Выбора команды нет: выдача идёт сразу по всем командам.
* **Массовая выдача**: кнопка вызывает `issue_all_above_threshold()` — он обходит `WPPA_Teams::all_teams()` и для каждой команды зовёт `issue_team_above_threshold()`, который берёт строки `WPPA_Participants::rows()`, баллы `scores()` и выдаёт сертификат только тем, у кого `below_threshold()` ложно. Наставники в список не попадают, участники без результатов тестов пропускаются. Порог — тот же `participant_min_percent`. Итоги суммируются: `issued`, `skipped`, `errors`.
* **Что попадает в сертификат**: получатель — имя и фамилия участника (`WPPA_Teams::full_name()`), email — из аккаунта, программа — название команды, подпись — имя куратора; процент и баллы уходят в `custom` как `percent` и `score` (плейсхолдеры `{custom_percent}`, `{custom_score}` в бланке WP Diplom). Всё переопределяется фильтром `wppa_certificate_args`.
* **Настройки**: «Настройки → Сертификаты» — `certificate_template` (ID бланка `wpdc_template`, 0 — бланк WP Diplom по умолчанию, фильтр `wppa_certificate_template`), `certificate_email` (отправлять письмо с PDF сразу при выдаче, `WPDC_Email::send()`, фильтр `wppa_certificate_send_email`).
* **Письмо о сертификате**: при выдаче письма нет — участнику пишет отдельная рассылка «Сертификаты» во вкладке «Рассылка» (см. ниже). Галочка «Письмо» в настройках осталась только для PDF от WP Diplom.
* **Наставник**: вкладка «Сертификаты» открыта и наставнику команды — под своими сертификатами он видит секцию «Сертификаты участников» (`WPPA_Certificates::team_rows()`: участники его команды, без наставников и без чужих команд). Колонки — участник, номер, программа, дата, скачивание PDF; отозванные помечены. Куратору эта секция не нужна — у него колонка «Сертификат» в блоке «Участники и баллы».
* **Что хранится**: мета участника `_wppa_certificates` — `cert-<ID> => { id, number, code, course, time, by, sent }`; список сортируется по дате выдачи, сначала новые.
* **Скачивание**: `admin-post.php?action=wppa_certificate_download&user=…&cert=…` с nonce `wppa_certificate_{user}_{cert}` (`WPPA_Certificates::download_url()`). Доступ — участнику и куратору (`can_view()`), PDF берётся из `WPDC_Certificate::pdf()`.
* **Проверка подлинности в кабинете не показывается**: участник видит только номер, программу, дату и «Скачать». Код проверки и ссылка на страницу проверки остаются в данных записи (`code`, `verify`) и доступны разработчику: `WPPA_Certificates::verify_url()` строит ссылку через `WPDC_Certificate::verify_url()` (бланк берётся из `_wpdc_template`), а без этого метода — `/certificate/{код}/`; фильтр `wppa_certificate_verify_url` (ссылка, код, ID сертификата) позволяет отдать свою. Чтобы показать их в кабинете, достаточно переопределить шаблон `templates/blocks/certificates-widget.php` в теме.
* **Отзыв**: `is_revoked()` читает `_wpdc_revoked` при каждом показе. Отозванный сертификат помечен значком «отозван», кнопка «Скачать» заменена пояснением, а `handle_download()` отвечает отказом — прямая ссылка тоже не работает. У куратора в списке участников пометка дублируется.
* **«Убрать»** убирает сертификат только из кабинета — в WP Diplom запись и PDF остаются.
* **Выгрузка PDF в отдельную папку**: каждый выданный сертификат автоматически сохраняется файлом с читаемым именем (`WPPA_Certificate_Export`). Папка — подпапка `certificate_export_dir` (по умолчанию «Сертификаты») внутри папки из настроек «Сетевая папка», а если она не задана — `uploads/wppa-certificates/Сертификаты`. Имя файла — шаблон `certificate_filename`, по умолчанию `{recipient_name}` (Фамилия Имя Отчество), есть подстановки `{number}`, `{team}`, `{date}`, `{email}`. Расширение `.pdf` добавляется само, при совпадении имени к файлу добавляется номер сертификата. Выгрузку включает галочка «Сохранять PDF каждого выданного сертификата в отдельную папку» (`certificate_export`, по умолчанию включена); фильтры — `wppa_certificate_export_enabled`, `wppa_certificate_export_folder`, `wppa_certificate_export_filename`. У куратора во вкладке «Участники» есть кнопка «Выгрузить PDF в папку» (`certificate_action=export_all`) для разовой выгрузки всего выданного.
* **Панель редактирования сертификатов**: куратор раскрывает выданный сертификат прямо в блоке «Сертификаты» и правит получателя, e-mail, программу, часы, преподавателя, дату выдачи, номер, бланк и галочку «отозван» (`certificate_action=update`). После сохранения PDF пересобирается (`WPDC_Certificate::pdf( $id, true )`) и файл в папке переписывается под актуальным именем — старый файл выгрузки удаляется. Кнопка «Пересобрать PDF» пересобирает без правки полей (`certificate_action=rebuild`), «Убрать из кабинета» скрывает запись у участника (`certificate_action=remove`). Пустые и кривые значения не затирают данные, а действие `wppa_certificate_updated` даёт хук на правку.
* **Формы**: `wppa_action=certificate` + `certificate_action=issue|issue_threshold|remove`, nonce `wppa_certificate` (поле `wppa_nonce`), обработчик — `WPPA_Certificates::handle_request()`.
* **Коды уведомлений**: `certificate_issued`, `certificate_issued_many`, `certificate_nobody`, `certificate_removed`, `certificate_missing`, `certificate_forbidden`, `certificate_unavailable`, `certificate_failed`.

## Переопределение шаблонов

Скопируйте нужный файл из `templates/` в `wp-content/themes/ваша-тема/wp-personal-account/` — плагин подхватит его автоматически (`WPPA_Template::locate()`).

Фильтры для доработок:

```php
add_filter( 'wppa_tabs', function ( $tabs ) {
	$tabs['support'] = 'Поддержка';
	return $tabs;
} );

add_filter( 'wppa_team_max_members', function () {
	return 25;
} );

add_filter( 'wppa_team_limit', function ( $limit, $team_id ) {
	return 10 === (int) $team_id ? 50 : $limit;
}, 10, 2 );

add_filter( 'wppa_team_min_members', function () {
	return 3;
} );

add_filter( 'wppa_team_min', function ( $min, $team_id ) {
	return $min;
}, 10, 2 );

add_filter( 'wppa_fields', function ( $fields ) {
	$fields['department'] = array(
		'section' => 'work',
		'label'           => 'Отдел',
		'type'            => 'text',
		'meta'            => '_wppa_department',
		'enabled_default' => 1,
	);
	return $fields;
} );

add_filter( 'wppa_min_password_length', function () {
	return 20;
} );

add_filter( 'wppa_notices', function ( $messages ) {
	$messages['profile_saved'] = array( 'success', 'Данные сохранены.' );
	return $messages;
} );
```

## Кнопка со ссылкой и таймер

Блок «Кнопка со ссылкой» ведёт на внешний адрес и открывается только при выполнении условий.

* **Период активности** — поля «с» и «по» (`datetime-local`, время сайта). Пустое поле — без ограничения с этой стороны. Несуществующие даты и время (30 февраля, месяц 13, часы 99) не сохраняются: проверка идёт по календарю, а не по шаблону строки.
* **Комментарий** — необязательный текст под кнопкой (настройка «Комментарий»). Выводится и у открытой, и у закрытой кнопки; переносы строк сохраняются, разметка вырезается (`sanitize_textarea_field`), пустой комментарий ничего не добавляет в разметку. В сообщение ожидания он не подменяет: системные сообщения остаются своими.
* **Условие «команда сформирована»** — кнопка активна, только когда в команде набран минимум участников (настройка «Минимум участников», наставник не считается).
* **Наставнику кнопка не выдаётся.** Наставник в команде наблюдатель: он не идёт ни в зачёт минимума, ни в состав. Блок для него не выводится вообще — ни открытым, ни серым с сообщением, ни с отсчётом. Проверка на стороне сервера (`WPPA_Link_Button::is_mentor()`), состояние `mentor` в `state()`; тема, переопределившая шаблон `blocks/link-button.php`, должна повторить этот ранний выход.
* Пока условия не выполнены, кнопка видна, но неактивна: `aria-disabled`, без `href`, рядом сообщение — «Ждём состав команды: 1 из 2 участников», «Откроется 05.11.2026 10:00», «Срок доступа истёк …».
* В окне ожидания выводится обратный отсчёт (`До открытия:` / `Осталось:`) — `д ч:м:с`, обновляется каждую секунду. Когда отсчёт доходит до нуля, страница перезагружается один раз, и сервер заново решает, открывать ли ссылку.
* Адрес ссылки не попадает в разметку, пока доступ закрыт: до открытия в HTML нет `href`, поэтому таймер нельзя обойти через исходный код.
* Блок ставится в любую вкладку через «Конструктор», по умолчанию добавлен на «Обзор». Для существующих установок блок добавляется в «Обзор» один раз при обновлении.

Фильтр настроек:

```php
add_filter( 'wppa_link_button', function ( $config ) {
	$config['text'] = 'Открыть комнату';
	return $config;
} );
```

Хелперы: `WPPA_Link_Button::config()` (включая `note`), `WPPA_Link_Button::state()`, `WPPA_Link_Button::team_progress()`, `WPPA_Link_Button::is_mentor()`, `WPPA_Link_Button::countdown_text()`.

## Сетевая локальная папка с авторизацией

Настройки → **«Сетевая локальная папка»**: один путь, логин и пароль. Тип подключения определяется по пути, как в `wordprees`:

| Путь в настройках | Что делает плагин |
| --- | --- |
| `\\fileserver\exchange\reports` | SMB по UNC |
| `smb://fileserver/exchange/reports` | SMB по URL |
| `smb://DOMAIN:pass@fileserver/share` | SMB, логин и пароль прямо в адресе |
| `/mnt/share/wppa` | обычная или смонтированная папка |

Порядок доставки:

1. **Windows** — UNC-путь доступен как обычная папка.
2. **Шара уже смонтирована** в систему — пишем по пути (`mount -t cifs`, `/etc/fstab`).
3. **Расширение `php-smbclient`** — запись напрямую, без монтирования.
4. **Утилита `smbclient`** — `smbclient //host/share -A файл_учётных_данных -c 'cd "dir"; put "…" "…"'`; сначала проверяются порты 445 / 139, отказ `NT_STATUS_LOGON_FAILURE` переводится в «сервер отклонил логин или пароль», отсутствие папки — в отдельное сообщение (выгрузка создаст её сама).

Внутри `-c` используются только двойные кавычки: smbclient не понимает одинарные и считает их частью имени папки.
5. Ничего нет — плагин показывает готовую команду `mount -t cifs` и просит поставить `smbclient`.

Домен указывается в логине: `WORKGROUP\svc_wppa`. Пароль по умолчанию хранится в настройках, но константа в `wp-config.php` важнее:

```php
define( 'WPPA_SMB_PASSWORD', 'пароль' );
```

Пароль никогда не попадает в командную строку: он пишется во временный файл с правами `0600` и удаляется после запуска. В режиме выгрузки выбирается способ записи — «Папка на сервере» или «Сетевая папка с логином и паролем».

```php
WPPA_SMB::config();                  // path, user, pass
WPPA_SMB::detect_type();             // filesystem | smb
WPPA_SMB::parse_path( $path );        // host, share, subdir, unc, service
WPPA_SMB::split_user( 'DOM\user' );  // domain, user
WPPA_SMB::test();                     // ok, message, method (filesystem|mounted|windows|extension|cli)
WPPA_SMB::write( $name, $csv );
WPPA_SMB::mount_command();
WPPA_SMB::temp_file( $name );       // временный файл: подключает wp-admin/includes/file.php сам
```

Фильтры: `wppa_smb` (настройки), `wppa_smb_runner` (запуск команд), `wppa_smb_port_check` (проверка портов).

Временные файлы создаются только через `WPPA_SMB::temp_file()`: `wp_tempnam()` объявлена в `wp-admin/includes/file.php`, а на фронтенде этот файл не подключён — прямой вызов давал `Call to undefined function wp_tempnam()` при сохранении профиля. Обёртка подключает файл сама, а если его нет — работает через `tempnam()`.

Выгрузка по изменению может выполняться внутри обычного запроса (сохранение профиля, смена роли в команде). Любая ошибка внутри неё перехватывается `Throwable`: пишется строка в журнал выгрузок, страница продолжает работать. Ожидание изменений снимается в любом случае, поэтому упавшая выгрузка не повторяется на каждое сохранение.

### Баллы за тесты (плагин олимпиад)

Если установлен плагин `wordprees` (олимпиады), плагин подхватывает результаты тестов **только для выгрузки аккаунтов**. В личном кабинете олимпиад нет: ни вкладки, ни блока — участник видит свои баллы в кабинете олимпиад, а не здесь.

Что даёт интеграция:

- в выгрузке появляется группа колонок «Баллы за тесты»: баллы, максимум баллов, процент;
- в баллы идут только зачтённые работы — статусы `completed` и `needs_review`; незавершённые, просроченные и дисквалифицированные не считаются;
- процент — сумма баллов к сумме максимумов, с десятичным разделителем локали сайта (`67,5`);
- плагин определяется по таблице `{prefix}olympiad_attempts` (или по классу `WPOlympiad\Attempt`) и кэшируется на час; если его нет — группы колонок не существует и запросов к базе нет.

```php
WPPA_Olympiad::is_active();
WPPA_Olympiad::results( $user_id );    // список попыток с названием теста
WPPA_Olympiad::totals( $user_id );     // tests, score, max_score, percentage, best, pending
WPPA_Olympiad::summary( $user_id );    // одна строка для сводок
WPPA_Olympiad::summary_map( $ids );    // сводка сразу по многим: один запрос GROUP BY user_id
WPPA_Olympiad::flush();                // сбросить кэш определения
```

Фильтры: `wppa_olympiad_active` (принудительно включить или выключить), `wppa_olympiad_counted_statuses` (какие статусы считать зачтёнными).

### Выгрузка по изменениям

В настройках выгрузки есть галочка **«Выгружать, когда меняются данные аккаунтов»** и задержка: сразу / 5 минут / 15 минут / час.

События, которые считаются изменением:

- регистрация и удаление пользователя
- сохранение профиля
- изменение любого поля `_wppa_*` (команда, роль, подтверждение email, персональные данные)
- настройки команды (минимум и лимит участников)

Служебные ключи (`_wppa_email_token`, `_wppa_email_token_expires`, `_wppa_team_invite_token`, `_wppa_team_invite_expires`) намеренно игнорируются — это техническая переписка, а не изменение данных.

Изменения подряд объединяются: причины копятся в одной очереди, а событие WP-Cron ставится один раз и **не переносится** новыми изменениями, иначе поток сохранений откладывал бы выгрузку бесконечно. При задержке «сразу» файл пишется синхронно. В журнале видно причину: «Выгрузка по изменению (регистрация пользователя #14, …)».

```php
WPPA_Export_Folder::note_change( 'причина' );  // запомнить изменение и запланировать выгрузку
WPPA_Export_Folder::pending();                 // причины ожидающей выгрузки
WPPA_Export_Folder::next_change();             // когда сработает
WPPA_Export_Folder::run_change();               // выполнить сейчас
WPPA_Export_Folder::delays();                   // варианты задержки
```

Выгрузка по изменениям дополняет расписание, а не заменяет его. Если файлов слишком много, поставь задержку побольше и `keep` поменьше.

## Возврат на ту же страницу после действия

Формы кабинета присылают скрытое поле `wppa_return` с адресом текущей страницы (`WPPA_Plugin::current_url()`). Обработчики (`WPPA_Certificates::handle_request()`, `WPPA_Curator_Files::handle_request()`) берут его через `WPPA_Plugin::posted_return( $fallback )`: адрес принимается, только если он ведёт на этот же сайт (сравнение хоста с `home_url()`), иначе используется прежний запасной адрес вкладки. Поэтому после выдачи или удаления сертификата, правки сертификата и загрузки файлов куратор остаётся на той же вкладке с той же открытой командой (`?wppa_team=ID`), а не попадает на общий список.

## Экспорт в сетевую папку (SMB)

Автоматическая выгрузка того же CSV в папку на диске — в том числе в смонтированную сетевую шару.

PHP не умеет говорить по SMB сам, поэтому шара монтируется на сервере, а плагин пишет по обычному пути:

```bash
mount -t cifs //server/share /mnt/share -o username=user,password=pass,uid=www-data
```

На Windows подойдёт UNC-путь `\\server\share\wppa` — файл пишется от имени пользователя, под которым работает PHP. Схемы `smb://` отклоняются: для них есть фильтр-обработчик (см. ниже).

**Настройки → «Экспорт в папку»**: галочка «Копировать файлы наставников в папки команд» (`file_export`: снята — файлы команд остаются в кабинете, экспорт CSV работает как обычно), включение автоматической выгрузки, путь, шаблон имени файла (`{date}`, `{time}`, `{datetime}`, `{site}`), расписание (вручную / каждый час / дважды в день / раз в день / раз в неделю + время), сколько файлов хранить (ротация), состав выгрузки (группы колонок, кого выгружать, разделитель, лимит строк).

**Инструменты → «Экспорт в сетевую папку (SMB)»**: состояние папки, время следующей выгрузки, кнопки «Экспортировать», «Проверить подключение к сетевой папке» и «Очистить журнал», журнал последних запусков (успех/ошибка, файл, сообщение).

Как устроено:

* файл пишется во временный `.tmp` и переименовывается — читатель не увидит половину выгрузки;
* после записи срабатывает ротация: остаются последние N файлов `*.csv` (0 — не удалять);
* каждый запуск (и ручной, и по расписанию) пишется в журнал, всего хранится 10 записей;
* расписание — обычный WP-Cron (`wppa_export_folder_event`), перенастраивается автоматически при изменении настроек; запуск происходит при обращении к сайту, для точного времени нужен системный cron на `wp-cron.php`;
* свой SMB-клиент подключается фильтром:

```php
add_filter( 'wppa_export_folder_writer', function ( $handled, $path, $csv ) {
	// true — записали сами, false — ошибка, null — писать штатно.
	return null;
}, 10, 3 );
```

Хелперы: `WPPA_Export_Folder::config()`, `check_folder()`, `write()`, `rotate()`, `logs()`, `next_run()`, `reschedule()`, `filename()`.

## Восстановление пароля

Ссылка «Забыли пароль?» больше не уводит на служебную страницу WordPress (`wp-login.php`) — весь сброс проходит в кабинете.

1. `?wppa_view=lostpassword` — форма «Укажите логин или email».
2. Письмо со ссылкой `?wppa_view=resetpass&wppa_login=…&wppa_key=…` (срок жизни 24 часа, одноразовая, как в ядре WP).
3. `?wppa_view=resetpass` — форма нового пароля с требованиями из `WPPA_Password` и `minlength` из настроек.
4. После сохранения — уведомление «Пароль обновлён» и переход к входу.

Что учтено:

* Ответ на заявку всегда одинаковый («если такой аккаунт есть, письмо отправлено») — нельзя перебором узнать, кто зарегистрирован на сайте.
* Повторная заявка по тому же логину/email — не чаще раза в минуту (транзиент, код `reset_too_fast`).
* Ключ проверяется `check_password_reset_key()`, пароль меняется `reset_password()` — то же, что в ядре, но интерфейс свой.
* Валидация пароля — общие правила (`WPPA_Password`), те же сообщения, что при регистрации и смене пароля.
* Ссылки и письмо можно переписать фильтрами `wppa_reset_password_subject` и `wppa_reset_password_body`.

```php
WPPA_Plugin::lost_password_url();            // ссылка на форму заявки
WPPA_Reset::reset_url( $login, $key );       // ссылка установки пароля
WPPA_Reset::validate( $key, $login );        // WP_User|null
WPPA_Reset::is_throttled( $login );          // защита от частых заявок
```

## Экспорт аккаунтов

Админка → «Инструменты» → «Экспорт аккаунтов». CSV собирается по группам колонок, а не одной плоской простынёй.

| Группа | Колонки |
| --- | --- |
| Учётная запись | логин, email, дата регистрации |
| Профиль | фамилия, имя |
| Личные данные | поля из настроек «Персональные данные»: встроенные и свои, в порядке разделов |
| Команда | команда, роль в команде, капитан, наставники, участников |
| Статусы | команда сформирована |
| Баллы за тесты | баллы, максимум баллов, процент (появляется при установленном плагине олимпиад; только в файле выгрузки)

* В файле нет числового ID пользователя: строку опознаёт логин — он уникален и не меняется. ID остаётся внутри плагина для шаблонов и фильтров.
* В файле также нет колонок «Отображаемое имя», «О себе» и «Email на подтверждении». Эти значения остаются в строке данных (`display_name`, `description`, `email_pending`), их по-прежнему читает фильтр `wppa_export_row`, но в CSV они не выводятся.
* Две строки заголовков: первая — названия групп, вторая — подписи полей. Так файл читается и глазами, и скриптом (вторая строка — стабильные имена колонок).
* Группы включаются галочками; «Учётная запись» выгружается всегда.
* Фильтр «Кого выгружать»: все, только с командой, только без команды, только из сформированных команд.
* Разделитель: `;` для Excel или `,` для Google Sheets. UTF-8 с BOM, чтобы Excel не ломал кириллицу.
* **Защита от формул.** Excel и LibreOffice выполняют всё, что начинается с `=`, `+`, `-`, `@`, табуляции или возврата каретки. Имя пользователя вида `=cmd|'/C calc'!A0` в файле выгрузки — команда на машине того, кто файл откроет. Такие значения помечаются апострофом (`WPPA_Export::safe_cell()`), числа не трогаются: минус перед числом — знак, а не формула. Префикс меняется фильтром `wppa_export_cell_prefix`.
* Лимит строк настраивается (по умолчанию 5000, максимум 20000).
* Имя файла: `wppa-accounts-YYYYMMDD-HHMMSS.csv`.

### Порядок строк: командами

Участники выгружаются не вперемешку по дате регистрации, а группами — по названию команды:

1. команды идут по алфавиту (без учёта регистра, `альфа` и `Альфа` рядом);
2. внутри команды: капитан → наставник → участники по имени;
3. пользователи без команды — в конце, по имени.

Так по файлу видно, кто в какой команде, и можно свернуть блоки в Excel. Строки не добавляются и не теряются: сортировка меняет только порядок, лимит и охват считаются как раньше.

Название команды берётся из записи команды. Если команда удалена, а мета у пользователя осталась, он попадает в конец — в файле у него пустая колонка «Команда», и он не притворяется участником несуществующей команды.

Отключить сортировку:

```php
add_filter( 'wppa_export_group_by_team', '__return_false' );
```

Расширение: фильтры `wppa_export_columns`, `wppa_export_row`, `wppa_export_group_by_team`, `wppa_export_decimal_separator`, класс `WPPA_Export` (`groups()`, `columns()`, `scopes()`, `row()`, `users()`, `sort_by_team()`, `sort_key()`, `percent()`, `decimal_separator()`, `header()`, `build()`, `csv()`, `send()`). Образец файла — `export-sample.csv` в репозитории.

## Панель WordPress на всех страницах

Настройка **«Основное» → «Панель WordPress»** (по умолчанию включена) скрывает админ-бар на страницах сайта и в админке для пользователей без права `manage_options`. Администраторов и суперадминистраторов плагин не ограничивает: видимость их панели определяется WordPress и другими плагинами. На мобильных экранах у остальных пользователей в админке остаётся штатная кнопка открытия меню.

* При выключении настройки плагин не меняет решение WordPress и других плагинов о видимости панели. Существующие настройки сохраняются.
* Скрытие — оформление, а не ограничение доступа: вход в `wp-admin` не закрывается.
* На сайте используется фильтр `show_admin_bar`; в админке WordPress обходит этот фильтр, поэтому панель скрывается стилями. Метод `WPPA_Plugin::maybe_hide_admin_bar()` сохранён для совместимости, но больше не подключён к хуку.

## Регистрация по таймеру

Приём заявок можно ограничить по времени — два поля `datetime-local` в **Настройки → «Основное» → «Приём заявок»** (время сайта, пустое поле — без ограничения с этой стороны).

* Внутри окна всё как обычно: форма, кнопки, отправка.
* **До начала**: вместо формы — заглушка «Форма регистрации откроется 05.11.2026 10:00» с обратным отсчётом; кнопка «Регистрация» (в форме входа, в блоке `wppa/register` с `display="button"`) неактивна и показывает отсчёт.
* **После окончания**: заглушка «Регистрация закончилась …», кнопки неактивны, отсчёта нет.
* Проверка **серверная**: `WPPA_Plugin::registration_live()` в обработчике формы. Отправка POST вне окна отклоняется с уведомлением `registration_not_yet` / `registration_over` — обойти через консоль или прямую отправку формы нельзя.
* Когда отсчёт доходит до нуля, страница перезагружается и форма открывается сама.

Хелперы и состояния:

```php
$window = WPPA_Plugin::registration_window();
// array( 'state' => 'none|before|open|after', 'start' => 0, 'end' => 0,
//        'message' => '', 'countdown' => 0, 'countdown_of' => 'open', 'limited' => bool )

WPPA_Plugin::registration_open(); // регистрация включена в настройках и в WordPress
WPPA_Plugin::registration_live(); // включена и открыта по времени — пускает заявки
```

Общие функции времени (`to_timestamp()`, `format_date()`, `sanitize_datetime()`, `countdown_text()`, `countdown_html()`) вынесены в класс `WPPA_Time` — он же используется кнопкой со ссылкой.

## Наставник: назначение в админке

Админка → **«Команды»**: у каждой команды в колонке «Наставники» есть выбор участника и кнопка «Наставник», рядом с действующим наставником — «снять». Капитан наставником быть не может, участник другой команды — тоже.

Каждое нажатие возвращает на ту же страницу с уведомлением, и причина отказа называется прямо, без общего «ошибка»:

| Что произошло | Сообщение |
| --- | --- |
| назначено / снято | «Наставник назначен» / «Роль наставника снята» |
| участник уже наставник | «Этот участник уже наставник» |
| снимают роль у того, у кого её нет | «У этого участника и так нет роли наставника» |
| выбран капитан | «Капитан не может быть наставником» |
| выбран человек из другой команды | «Этот пользователь не состоит в выбранной команде» |
| форма устарела или прав не хватило | «Страница устарела…» / «Недостаточно прав» |
| внутри действия случилась ошибка PHP | «Действие не выполнено: на сайте произошла ошибка. Подробности записаны в журнал ошибок PHP» |

Раньше на истёкший nonce и нехватку прав WordPress показывал свой красный экран («Ссылка, по которой вы перешли, устарела»). Теперь плагин сам проверяет `wp_verify_nonce()` и права и возвращает назад с понятным текстом.

Логика вынесена в `WPPA_Admin::mentor_action( $tool, $team_id, $member_id )` — возвращает код уведомления и ничего не перенаправляет, поэтому проверяется тестами без HTTP.

## Наставник как обязательное условие

Настройка **«Требовать наставника»** (по умолчанию включена) делает наличие наставника обязательным условием сформированности команды.

* `WPPA_Teams::require_mentor()` — включено ли требование (фильтр `wppa_require_mentor`).
* `WPPA_Teams::has_mentor( $team_id )` — есть ли в команде наставник.
* `WPPA_Teams::is_missing_mentor( $team_id )` — не хватает наставника при включённом требовании.
* `WPPA_Teams::is_complete( $team_id )` — команда сформирована: набран минимум участников **и** (если требуется) есть наставник.
* `WPPA_Teams::gaps( $team_id )` — что мешает: `array( 'members' => 1, 'mentor' => true )`.

Где учитывается:

| Место | Что показывает |
| --- | --- |
| Вкладка «Команда» | отдельное уведомление «В команде нет наставника…», бейдж «Команда сформирована» |
| «Сводка профиля» на «Обзоре» | бейдж «Команда не сформирована» / «Команда сформирована» |
| Админка → «Команды» | бейджи «нет наставника» и «сформирована» |
| Блок «Кнопка со ссылкой» | условие «команда сформирована» не выполняется: «Ждём наставника: в команде пока нет наставника» |

Правило про наставника не меняет подсчёт: наставник по-прежнему не занимает место в лимите и не идёт в зачёт минимума участников.

## Оформление: цвета и стили

Внешний вид кабинета настраивается без правки кода: **«Личный кабинет → Настройки → Оформление»**.

| Настройка | Ключ `wppa_settings` | Переменная | По умолчанию |
| --- | --- | --- | --- |
| Акцентный цвет | `accent_color` | `--wppa-accent` | `#2563eb` |
| Акцент при наведении | `accent_hover_color` | `--wppa-accent-hover` | пусто — затемнение на 12% |
| Текст на акцентном фоне | `accent_contrast_color` | `--wppa-accent-contrast` | пусто — подбирается по яркости |
| Фон страницы | `color_bg` | `--wppa-bg` | `#f8fafc` |
| Фон карточек | `color_surface` | `--wppa-surface` | `#ffffff` |
| Основной текст | `color_text` | `--wppa-text` | `#0f172a` |
| Второстепенный текст | `color_muted` | `--wppa-muted` | `#64748b` |
| Рамки и разделители | `color_border` | `--wppa-border` | `#e2e8f0` |
| Подложки и наведение | `color_surface_alt` | `--wppa-surface-alt` | `#f1f5f9` |
| Успех | `color_success` | `--wppa-success` | `#047857` |
| Предупреждение | `color_warning` | `--wppa-warning` | `#b45309` |
| Ошибка и удаление | `color_danger` | `--wppa-danger` | `#b91c1c` |
| Информация | `color_info` | `--wppa-info` | `#0284c7` |
| Скругление карточек | `radius` | `--wppa-radius` | `14px` (0–32) |
| Текст заголовка | `heading_text` | — | «Личный кабинет» |
| Показывать заголовок | `heading_show` | — | 1 (пустой текст — не выводится) |
| Тег заголовка | `heading_tag` | — | `h1` (`h1`/`h2`/`h3`/`div`) |
| Размер надписи | `heading_size` | `--wppa-heading-size` | `22px` (12–72) |
| Насыщенность | `heading_weight` | `--wppa-heading-weight` | `700` (400–800) |
| Регистр | `heading_case` | `--wppa-heading-case` | `none` (`uppercase`/`capitalize`/`lowercase`) |
| Выравнивание | `heading_align` | `--wppa-heading-align` | `left`/`center`/`right` |
| Цвет надписи | `heading_color` | `--wppa-heading-color` | пусто — цвет основного текста |
| Отступ снизу | `heading_gap` | `--wppa-heading-gap` | `18px` (0–64) |
| Скрыть заголовок темы | `hide_page_title` | — | 1 |
| Свой CSS | `custom_css` | — | пусто |

* **Класс** — `WPPA_Theme` (`includes/class-wppa-theme.php`): `defaults()`, `get()`, `sanitize()`, `vars()`, `css()`, `style_tag()`, `presets()`, `contrast_color()`, `darken()`, `normalize_hex()`, `clamp_radius()`, `is_default()`.
* **Весь текст на переменных**: в `assets/css/account.css` нет ни одного жёсткого `color: #…` — только `var(--wppa-*)`, `inherit` или `transparent`. Заголовки (`h1…h6`, `.wppa-title`, `.wppa-subtitle`), таблицы, подписи полей и плейсхолдеры получают цвет явно, а не по наследству: стили темы (`h2 { color: … }`, `p { color: … }`) перебивают наследование, из-за чего раньше часть текста не перекрашивалась. Уведомления и значки используют цвета статусов: `--wppa-success`, `--wppa-warning`, `--wppa-danger`, `--wppa-info`.
* **Производные цвета считаются на месте**: подложки и рамки статусов — `color-mix(in srgb, var(--wppa-success) 12%, var(--wppa-surface))` и т.п. (`--wppa-success-soft`, `--wppa-success-line`, `--wppa-warning-soft`, `--wppa-danger-line`, `--wppa-accent-soft`…), тени — `color-mix` от цвета текста. Поэтому своя палитра (в том числе тёмная) не оставляет светлых пятен и не требует подбирать оттенки вручную.
* **Куда попадают значения**: `WPPA_Theme::css()` отдаёт `:root,.wppa,.wppa--guest,.wppa--widget{--wppa-accent:…;…}` и приклеивает `custom_css` — этот блок `wp_add_inline_style()` добавляет к стилям кабинета (`WPPA_Plugin::register_assets()`) и к блоку Gutenberg (`WPPA_Blocks::enqueue_styles()`). Селекторы перечисляют контейнеры намеренно: значения по умолчанию объявлены в `assets/css/account.css` на `.wppa`, поэтому одного `:root` мало — правило должно попадать в тот же элемент и печататься позже файла стилей. Список расширяется фильтром `wppa_theme_selectors`.
* **Авто-значения**: пустой `accent_hover_color` считается как `WPPA_Theme::darken()` (на 12% темнее акцента), пустой `accent_contrast_color` — по яркости фона (WCAG): на светлом акценте тёмный текст, на тёмном — белый.
* **Готовые наборы**: кнопки «Синяя», «Зелёная», «Фиолетовая», «Тёмная» подставляют все цвета — основные и статусные — в поля (`WPPA_Theme::presets()`); сохраняются только после «Сохранить». У тёмного набора статусные цвета светлее, чтобы читались на тёмных карточках.
* **Группы в форме**: `WPPA_Theme::groups()` делит поля на «Основные цвета» и «Уведомления и статусы».

### Заголовок кабинета

Надпись «Личный кабинет» над кабинетом выводит сам плагин — в `templates/account.php` перед шапкой: `WPPA_Theme::heading()` отдаёт текст, тег и стиль, а печатается `<h1 class="wppa-title wppa-page-title">…</h1>` (тег из настройки, атрибуты экранируются).

* **Свой текст**: `heading_text` — по умолчанию «Личный кабинет»; пустая строка или снятая галочка `heading_show` — заголовка нет вовсе.
* **Стиль**: `heading_size` (12–72 px), `heading_weight` (400/500/600/700/800), `heading_case`, `heading_align`, `heading_color` (пусто — цвет основного текста), `heading_gap` (0–64 px). Значения уходят в переменные `--wppa-heading-*`, поэтому те же правила оформляют и заголовки внутри кабинета: формы входа и регистрации, профиль, команду, файлы (`WPPA_Theme::heading_css()`).
* **Заголовок темы**: страницы, созданные WordPress, печатают свой `<h1>` (`.entry-title`, `.page-title`, `.wp-block-post-title`, `.entry-header h1`). Галочка `hide_page_title` (по умолчанию включена) скрывает его **только на странице кабинета** — селектор строится от `body.page-id-{account_page_id}`; если страница кабинета не выбрана, правило не выводится, чтобы не пропали заголовки всех страниц сайта.
* **Проверка в тестах**: рендер `templates/account.php` с разными настройками — свой тег и текст, отключение, пустой текст; плюс наличие переменных и правила скрытия в `WPPA_Theme::css()`.
* **Предпросмотр**: в настройках заголовок в карточке меняется вместе с полями (`assets/js/admin-theme.js`, `[data-wppa-heading-text]`), в `preview.html` — блок «Заголовок кабинета» с тремя вариантами надписи.
* **Предпросмотр**: карточка с вкладками и кнопкой перекрашивается сразу при изменении цвета или ползунка скругления — до сохранения (`assets/js/admin-theme.js`, подключается только на странице настроек).
* **Валидация**: цвета принимаются как `#abc` и `#aabbcc` (приводятся к нижнему регистру), мусор заменяется значением по умолчанию; радиус обрезается до 0–32; из `custom_css` вырезаются теги (включая `<style>`), остаётся только текст стилей. Галочка «Вернуть оформление по умолчанию» (`theme_reset`) сбрасывает цвета, радиус и свой CSS.
* **Значения по умолчанию совпадают с CSS**: если ничего не настраивать, кабинет выглядит как раньше, а `WPPA_Theme::is_default()` в настройках подсказывает, что используется базовое оформление.
* **Где посмотреть**: `preview.html` — блок «Оформление: цвета и стили» с четырьмя наборами на одной форме входа; `preview-admin.html` — страница настроек с полями, ползунком и предпросмотром.

## Пароли

Пароль проверяется по набору правил — при регистрации и при смене пароля, на сервере и в браузере.

| Правило | Что требует | Сообщение при ошибке |
| --- | --- | --- |
| `length` | минимум 16 символов | «Пароль должен быть не короче 16 символов.» |
| `uppercase` | заглавная буква | «…хотя бы одну заглавную букву.» |
| `lowercase` | строчная буква | «…хотя бы одну строчную букву.» |
| `digit` | цифра | «…хотя бы одну цифру.» |
| `special` | спецсимвол (`! @ # $ %` …) | «…хотя бы один спецсимвол.» |
| `variety` | не меньше 8 разных символов | «Пароль слишком однообразный…» |
| `no_repeat` | без повторов `aaa`, `111` | «…не должен содержать повторов вида «aaa»…» |
| `no_sequence` | без `1234`, `abcd`, `qwer`, `asdf`, `zxcv` | «…последовательностей вида «1234»…» |
| `not_common` | не из словаря частых паролей | «Этот пароль слишком распространён…» |
| `not_personal` | без email, логина и имени | «Пароль не должен содержать ваш email, логин или имя.» |

* Проверка серверная (`WPPA_Password::error_code()`), первая же непройденная правило даёт своё сообщение — пользователь видит конкретную причину отказа, а не общее «слабый пароль».
* Под полем пароля выводится список требований, который подсвечивается по мере ввода: зелёный ✓ — выполнено, красный — нет. Работает и в регистрации, и в смене пароля.
* Правила включаются и выключаются в **Настройки → «Требования к паролю»** (снятая галочка — правило не проверяется ни на сервере, ни в браузере).
* Длина по умолчанию 16, меняется фильтром `wppa_min_password_length`.
* Свои правила — фильтром `wppa_password_rules`, свой словарь — `wppa_common_passwords`:

```php
add_filter( 'wppa_password_rules', function ( $rules ) {
	$rules['no_space'] = array(
		'code'            => 'password_no_space',
		'label'           => 'Без пробелов',
		'enabled_default' => 1,
		'client'          => 0,
		'test'            => function ( $password ) {
			return false === strpos( $password, ' ' );
		},
	);
	return $rules;
} );
```

* Хелперы: `WPPA_Plugin::min_password_length()`, `WPPA_Plugin::password_too_short()`, `WPPA_Password::error_code()`, `WPPA_Password::failed()`, `WPPA_Password::labels()`, `WPPA_Password::render_requirements()`.

## Безопасность

* Nonce на каждой форме (`check_admin_referer`), проверка `is_user_logged_in()`.
* Экранирование вывода: `esc_html`, `esc_attr`, `esc_url`, `wp_kses_post`.
* Санитизация ввода: `sanitize_text_field`, `sanitize_email`, `sanitize_textarea_field`, `absint`.
* Смена email — только по ссылке с токеном (`wp_hash_password` + срок 24 часа).
* Команды: приглашения и переименование — только капитан или наставник этой команды (`WPPA_Teams::is_manager_of()`, `is_captain_of()`), состав правит и куратор, действия защищены nonce, приглашения живут 7 дней и перегенерируются.
* Лимит попыток входа: 5 за 15 минут на IP (transient).
* Пароли никогда не логируются и не санитизируются (передаются как есть).

## Версионирование

Версия плагина — строго `X.Y.Z` (semver) и хранится в трёх местах, которые обязаны совпадать:

| Место | Строка |
| --- | --- |
| `wp-personal-account.php` | `* Version: 3.60.0` |
| `wp-personal-account.php` | `define( 'WPPA_VERSION', '3.60.0' )` |
| `readme.txt` | `Stable tag: 3.60.0` |

Правила инкремента:

* **X (major)** — ломающие изменения: переименование фильтров, удаление шаблонов, изменение структуры настроек.
* **Y (minor)** — новая функциональность без поломок: вкладки, шорткоды, интеграции.
* **Z (patch)** — багфиксы, стили, тексты.

### Сборка релиза

```bash
./tools/release.sh --check      # проверить, что все три версии совпадают и в формате X.Y.Z
./tools/release.sh 1.1.0        # выставить версию и собрать ../wp-personal-account-1.1.0.zip
./tools/release.sh 1.1.0 ~/dist # архив в свою папку
```

Скрипт сам синхронизирует все три точки версии, прогоняет `php -l` по всем файлам и дымовой тест шаблонов, а затем собирает архив `wp-personal-account-X.Y.Z.zip` без служебных файлов (`.git`, `tools/`, `preview.html`, `phpcs.xml.dist`).
